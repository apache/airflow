SQLExecuteQueryOperator to connect to Oracle
--------------------------------------------

Use the :class:`SQLExecuteQueryOperator<airflow.providers.common.sql.operators.sql>` to execute
Oracle commands in a `Oracle <https://docs.oracle.com/en/>`__ database.

.. note::
    Previously, ``OracleStoredProcedureOperator`` was used to perform this kind of operation. After deprecation this has been removed. Please use ``SQLExecuteQueryOperator`` instead.

Using the Operator
^^^^^^^^^^^^^^^^^^

Use the ``conn_id`` argument to connect to your Oracle instance where
the connection metadata is structured as follows:

.. list-table:: Oracle Airflow Connection Metadata
   :widths: 25 25
   :header-rows: 1

   * - Parameter
     - Input
   * - Host: string
     - Oracle database hostname
   * - Schema: string
     - Schema to execute SQL operations on by default
   * - Login: string
     - Oracle database user
   * - Password: string
     - Oracle database user password
   * - Port: int
     - Oracle database port (default: 1521)
   * - Extra: JSON
     - Additional connection configuration, such as DSN string:
       ``{"dsn": "(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=<hostname>)(PORT=1521))(CONNECT_DATA=(SERVICE_NAME=<service_name>)))"}``

Reference
^^^^^^^^^
For further information, look at:

* `Oracle Documentation <https://docs.oracle.com/en/>`__

.. note::

  Parameters given via SQLExecuteQueryOperator() are given first-place priority
  relative to parameters set via Airflow connection metadata (such as ``schema``, ``login``, ``password`` etc).


.. _howto/operator:OracleVectorOperators:

Oracle AI Vector Search Operators
---------------------------------

The Oracle provider includes operators and a hook for storing documents and
searching embeddings with Oracle AI Vector Search. The operators use the
existing :ref:`Oracle connection <howto/connection:oracle>` and default to the
``oracle_default`` connection ID.

Prerequisites
^^^^^^^^^^^^^

The target database must support the Oracle ``VECTOR`` data type,
``VECTOR_DISTANCE`` searches, and vector indexes. The database user must also
have the privileges required to create and modify the tables and indexes used
by the operators.

The provider accepts embeddings generated by the caller. It does not currently
generate embeddings with a model or with an Oracle database function. Sparse
vectors require Oracle Database 23.7 or later and a python-oracledb version
that provides ``oracledb.SparseVector`` (3.0.0 or later). See the `Oracle AI
Vector Search User's Guide <https://docs.oracle.com/en/database/oracle/oracle-database/23/vecse/ai-vector-search-users-guide.pdf>`__
and the `python-oracledb vector data documentation
<https://python-oracledb.readthedocs.io/en/stable/user_guide/vector_data_type.html>`__.

Create a vector table
^^^^^^^^^^^^^^^^^^^^^

Use :class:`~airflow.providers.oracle.operators.oracle_vector.OracleCreateVectorTableOperator`
to create a table with the following columns:

.. code-block:: sql

    id VARCHAR2(512) PRIMARY KEY
    text CLOB NOT NULL
    metadata JSON
    embedding VECTOR(<dimension>, <format> [, SPARSE]) NOT NULL

The default embedding format is ``FLOAT32``. Dense vectors also support
``FLOAT64``, ``INT8``, ``BINARY``, and ``FLEXIBLE``. Sparse vectors support
``FLOAT32``, ``FLOAT64``, and ``INT8`` only. Use ``id_column``, ``text_column``,
``metadata_column``, and ``embedding_column`` to use different column names.

Set ``overwrite=True`` to drop and recreate an existing table. It cannot be
combined with ``if_not_exists=True``.

Add documents
^^^^^^^^^^^^^

Use :class:`~airflow.providers.oracle.operators.oracle_vector.OracleAddVectorDocumentsOperator`
to insert documents. Each document is either a mapping with ``id``, ``text``,
``metadata``, and ``embedding`` keys or an
:class:`~airflow.providers.oracle.hooks.oracle_vector.OracleVectorDocument`.
``documents`` and ``documents_callable`` are mutually exclusive. The callable
receives the task context and returns the documents to insert.

Embeddings must have the same dimension as the vector column. ``batch_size``
controls the size of batched inserts. Set ``mutate_on_duplicate=True`` to
update the text, metadata, and embedding when a document ID already exists.

Create a vector index
^^^^^^^^^^^^^^^^^^^^^

Use :class:`~airflow.providers.oracle.operators.oracle_vector.OracleCreateVectorIndexOperator`
to create an approximate vector index after loading the table:

* ``HNSW`` creates an in-memory neighbor graph. Use ``neighbors`` and
  ``ef_construction`` for HNSW indexes.
* ``IVF`` creates neighbor partitions. Use ``neighbor_partitions`` for IVF
  indexes.
* ``accuracy`` must be between 1 and 100, and ``parallel`` controls parallel
  index creation.
* ``EUCLIDEAN``, ``COSINE``, and ``DOT`` are supported distance metrics.

Search for similar documents
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Use :class:`~airflow.providers.oracle.operators.oracle_vector.OracleVectorSearchOperator`
to search by a supplied embedding. ``query`` may contain the original query
text, but it is currently retained for compatibility and logging; it does not
generate an embedding. Supply ``embedding`` for every search.

The ``filter`` argument applies comparisons to fields in the JSON metadata
column. It supports ``$eq``, ``$ne``, ``$gt``, ``$lt``, ``$gte``, ``$lte``,
``$between``, ``$like``, ``$startsWith``, ``$hasSubstring``, ``$instr``,
``$in``, ``$nin``, ``$exists``, and ``$not``. Combine expressions with
``$and``, ``$or``, and ``$nor``.

Range operators (``$gt``, ``$lt``, ``$gte``, ``$lte``, and ``$between``)
support numeric JSON metadata values. Use the text operators for string values;
date and datetime metadata comparisons are not currently supported.

The operator returns a list of XCom-safe dictionaries with ``id``, ``text``,
``metadata``, ``distance``, and ``embedding`` keys. Set ``include_score`` and
``include_embedding`` to control whether the corresponding values are
populated. Dense embeddings are returned as lists. Sparse embeddings are
returned as dictionaries containing ``num_dimensions``, ``indices``, and
``values``.

Delete documents
^^^^^^^^^^^^^^^^

Use :class:`~airflow.providers.oracle.operators.oracle_vector.OracleDeleteVectorDocumentsOperator`
to delete documents by ID. The
:class:`~airflow.providers.oracle.hooks.oracle_vector.OracleVectorHook` also
provides ``get_by_ids`` and ``drop_vector_index`` for direct hook-based table
and index management:

.. code-block:: python

    from airflow.providers.oracle.hooks.oracle_vector import OracleVectorHook

    hook = OracleVectorHook(oracle_conn_id="oracle_default")
    documents = hook.get_by_ids(table_name="AIRFLOW_VECTOR_DOCS", ids=["doc-1"])
    hook.drop_vector_index(index_name="AIRFLOW_VECTOR_DOCS_HNSW_IDX")

Unsupported features
^^^^^^^^^^^^^^^^^^^^

The following APIs are reserved for future support and currently raise
``NotImplementedError``: database-side embedding generation, ONNX model
loading and removal, and max-marginal-relevance search. Use client-side
embeddings with the supported operators and hook methods for now.
