Fix the secrets masker returning non-string values in cleartext when the key name is sensitive. ``SecretsMasker._redact_all`` — the fail-closed path taken once ``should_hide_value_for_key`` matches — only replaced ``str`` values and returned every other scalar unchanged, so an all-digit PIN, account number or API key stored under a ``*_password``/``*_token`` key was returned unmasked by ``GET /api/v2/variables`` while an equivalent alphanumeric value was masked correctly. Values of any type are now replaced, and only containers are traversed.
