Add a new Execution API version (``2026-11-13``) that lets a running task clear only the failed tasks of an existing Dag run (and their downstream) instead of resetting the whole run. This backs the opt-in ``auto_clear_failed_tasks`` flag on ``TriggerDagRunOperator``: when a triggered child Dag run has already failed, re-running the parent task (for example on a retry) clears only the failed tasks so the child resumes from its point of failure while preserving already-succeeded tasks. ``reset_dag_run`` still takes precedence when both are set, and against an older core the operator raises ``NotImplementedError`` rather than silently falling back to a whole-run clear.
