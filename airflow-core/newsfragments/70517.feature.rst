Add a ``[metrics] statsd_socket_path`` option to submit StatsD or Datadog metrics over a Unix Domain Socket. ``statsd_host`` / ``statsd_port`` are now nullable, so only explicitly-configured values are passed to the client (letting the Datadog client fall back to its own env vars when unset). If ``statsd_socket_path`` is set together with ``statsd_host`` / ``statsd_port``, the socket takes precedence and a warning is logged.
