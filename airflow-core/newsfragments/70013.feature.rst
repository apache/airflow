Added a new ``scheduler.dagruns.queued`` metric alongside the existing ``scheduler.dagruns.running`` metric, so operators can track queued DagRun backlog (e.g. Dags stuck behind ``max_active_runs`` limits or pool exhaustion) as well as running load. Both metrics are emitted as a single untagged aggregate value across all Dags by default, matching the previous behaviour of ``scheduler.dagruns.running``. Set ``[scheduler] dagrun_metrics_per_dag_id`` to ``True`` to instead emit one gauge per ``dag_id`` (tagged by ``dag_id``) for per-Dag visibility. This is opt-in because it increases the number of metric series sent to StatsD/OpenTelemetry proportionally to the number of Dags with active DagRuns.
