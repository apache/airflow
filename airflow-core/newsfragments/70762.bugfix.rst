+Temporal partition mappers (``StartOfHourMapper``, ``StartOfDayMapper``, ``StartOfWeekMapper``, ``StartOfMonthMapper``, ``StartOfQuarterMapper``, ``StartOfYearMapper``) now accept upstream partition keys that are already at (or coarser than) the mapper's own granularity, instead of raising ``ValueError`` when the key doesn't match ``input_format``. A key that doesn't match ``input_format`` is now also tried against the mapper's ``output_format``, so e.g. a day-level key such as ``"2026-07-30"`` no longer needs an explicit ``input_format`` override to be accepted by ``StartOfDayMapper``, and a mapper's own downstream output can be fed back into another instance of itself.
