Airflow's OpenTelemetry span id generator is now registered under the ``opentelemetry_id_generator`` entry point group, so deployments using OpenTelemetry auto-instrumentation or a vendor distro can select it with ``OTEL_PYTHON_ID_GENERATOR=airflow`` instead of importing a private Airflow module. When a ``TracerProvider`` has already been installed by someone else and the variable is not set, Airflow now patches the generator onto that provider and logs a warning, rather than silently losing it. In both cases Airflow contributes only the generator and leaves that provider's exporters untouched, so the deprecated ``[traces]`` endpoint options (``otel_host``, ``otel_port``, ``otel_ssl_active``, ``otel_service``) do not apply to it.
