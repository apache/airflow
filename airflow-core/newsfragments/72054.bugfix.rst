Fix DAG runs belonging to a completed backfill getting stuck in ``queued`` forever. Cancelling a backfill sets ``is_paused=True`` and ``completed_at`` on the backfill record. If one of that backfill's DAG runs was later cleared, it returned to the ``queued`` state but the scheduler's promotion query skipped any run whose backfill is paused, ignoring ``completed_at``. Such runs could never start again. The scheduler now treats ``is_paused`` as meaningful only while a backfill is still running, so runs tied to an already-completed backfill are schedulable again and previously stranded runs recover automatically.
