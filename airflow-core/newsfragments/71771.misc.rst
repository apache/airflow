Deprecate ``DagFileProcessorManager.persist_parsing_result``; override ``persist_parsing_results`` instead, which is handed a group of the files that finished parsing together. Overriding ``handle_parsing_result`` is still supported, but stops parse results being persisted a group at a time. Because a group records where its files ended up rather than how they got there, an import error raised and resolved within one group is no longer written, so ``on_new_dag_import_error`` is not called for it.
