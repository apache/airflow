Added a new ``on_task_instance_up_for_retry`` listener hook, fired when a task instance is set to ``UP_FOR_RETRY`` after a failure. This fires in addition to ``on_task_instance_failed`` (which continues to fire for both the retry and terminal-failure cases, unchanged, for backward compatibility) -- use the new hook to distinguish a task's automatic retries from its terminal failures without inspecting ``task_instance.state`` yourself.
