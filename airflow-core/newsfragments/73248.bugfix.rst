Migration ``0049`` no longer aborts on PostgreSQL when an XCom value cannot be represented as ``JSONB``. A single ``jsonb`` document cannot hold more than 268435455 bytes of array elements or object pairs, while the Airflow 2 ``bytea`` column allowed up to 1 GB, so the conversion could fail with ``ProgramLimitExceeded`` and leave the upgrade stuck at revision ``9fc3fc5de720``. Such values are now moved to the ``_xcom_archive`` table alongside the pickled values the migration already archives, and their ``dag_id``/``task_id``/``run_id``/``key`` are printed, so the upgrade completes. The rows are identified by attempting the conversion rather than by size, because ``jsonb`` can be larger than the text it is parsed from.
