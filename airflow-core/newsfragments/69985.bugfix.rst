Fix scheduler crash from deadline callbacks whose kwargs is a dict, nested or not. Migration ``0094`` (``replace_deadline_inline_callback_with_fkey``) built ``callback.data`` by wrapping only the outer object, leaving ``kwargs`` itself (and anything nested inside it) unencoded -- so ``BaseSerialization.deserialize`` raised ``KeyError`` on read for any dict-shaped ``kwargs``, not just ones with further nested structure, and the scheduler entered CrashLoopBackOff. Both the Postgres and MySQL/SQLite upgrade paths now extended-serialize the callback data recursively (and the downgrade path decodes it back). Deployments already upgraded across ``0094`` must repair existing ``callback.data`` rows out of band. (#69980)
