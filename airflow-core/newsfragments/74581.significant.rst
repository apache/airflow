psycopg3 statement preparation is now disabled by default

Airflow 3.4 makes psycopg3 the default Postgres driver for the metadata database. psycopg3 prepares a statement server-side once it has been executed ``prepare_threshold`` times (5 by default). Airflow now sets ``prepare_threshold = None`` on both the sync and async psycopg3 engines, which turns that off.

**Who changes behaviour:** no released version picked psycopg3 by itself, so this takes nothing away from an existing default installation. It applies to you if you already point ``sql_alchemy_conn`` or ``sql_alchemy_conn_async`` at ``postgresql+psycopg://`` or ``postgresql+psycopg_async://`` explicitly -- those deployments silently stop preparing statements on upgrade.

**Why:** a pooler running in transaction mode routes consecutive transactions on one client connection to different server connections, so unless it tracks prepared statements itself, queries begin failing with ``InvalidSqlStatementName`` -- or ``DuplicatePreparedStatement`` where several clients generate the same statement name -- once the threshold is crossed. The Airflow Helm chart sets ``pool_mode = transaction`` and ships PgBouncer 1.23.1 without setting ``max_prepared_statements``, so the recommended deployment is one of the affected ones.

Preparation is turned off outright rather than only having its threshold raised, so Postgres re-parses each statement and bulk ``executemany`` writes no longer reuse a single prepared statement.

**To keep statement preparation** you need both halves; restoring ``prepare_threshold`` alone will reintroduce the failures above unless the pooler can handle it.

First, make the pooler safe for it. With PgBouncer that means 1.22 or newer, ``max_prepared_statements`` set above 0 (it defaults to 0 until 1.24, where it becomes 200), and ``libpq`` 17 or newer on the Airflow side -- see `the psycopg documentation <https://www.psycopg.org/psycopg3/docs/advanced/prepare.html#using-prepared-statements-with-pgbouncer>`_. Running without a pooler at all is also fine.

Then put the setting back, by pointing ``sql_alchemy_connect_args`` at a dictionary defined in your ``airflow_local_settings.py``:

.. code-block:: ini

    [database]
    sql_alchemy_connect_args = airflow_local_settings.PSYCOPG3_CONNECT_ARGS

.. code-block:: python

    PSYCOPG3_CONNECT_ARGS = {"prepare_threshold": 5}

Anything set there is merged over the default and wins. The same applies to ``sql_alchemy_connect_args_async`` for the async engine.
