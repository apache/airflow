psycopg3 statement preparation is now disabled by default

Airflow 3.4 makes psycopg3 the default Postgres driver for the metadata database. psycopg3 prepares a statement server-side once it has been executed ``prepare_threshold`` times (5 by default). A connection pooler running in transaction mode routes consecutive transactions on one client connection to different server connections, so a pooler that does not track prepared statements itself cannot honour that, and tasks begin failing with ``DuplicatePreparedStatement`` once the threshold is crossed.

Airflow now sets ``prepare_threshold = None`` on both the sync and async psycopg3 engines, which disables the behaviour.

**Who this affected:** PgBouncer gained prepared-statement tracking in 1.24, where ``max_prepared_statements`` defaults to 200. The Airflow Helm chart sets ``pool_mode = transaction`` and ships PgBouncer 1.23.1, so the recommended deployment was an affected one. Other poolers may not support prepared statements at all.

**To keep statement preparation**, if your pooler tracks prepared statements or you run without one, point ``sql_alchemy_connect_args`` at a dictionary defined in your ``airflow_local_settings.py``:

.. code-block:: ini

    [database]
    sql_alchemy_connect_args = airflow_local_settings.PSYCOPG3_CONNECT_ARGS

.. code-block:: python

    PSYCOPG3_CONNECT_ARGS = {"prepare_threshold": 5}

Anything set there takes precedence over the default. The same applies to ``sql_alchemy_connect_args_async`` for the async engine.
