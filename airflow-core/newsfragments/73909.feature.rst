Dag authors can declare ``param_presets``, named sets of param values that the trigger form offers in a ``Preset`` drop-down; picking one loads the Dag's param defaults with that preset's values applied on top and leaves every field editable, a preset lists only the params it changes, and presets are validated at parse time so a key naming no declared param or a value failing that param's schema fails Dag parsing rather than surfacing at trigger time.
