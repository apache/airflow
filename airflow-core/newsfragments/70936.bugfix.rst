Fix API clients discarding JSON error bodies when a reverse proxy rewrites the ``content-type`` header. The media type was compared to the literal ``application/json``, so ``application/json; charset=utf-8`` or ``application/problem+json`` skipped error parsing entirely: ``airflowctl`` printed a raw ``httpx.HTTPStatusError`` traceback in place of the server's message, and in the Task SDK the exception was no longer a ``ServerResponseError``, so the status-specific handling in the supervisor and the task runner stopped matching. Two adjacent ``airflowctl`` crashes are fixed with it — a non-object JSON error body made the warning log raise, and a body labelled JSON that does not decode raised ``ValueError`` instead of falling through to ``raise_for_status()``.
